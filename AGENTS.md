# Working in this repo

## Always open a PR

Finish every change by opening a pull request, without being asked: branch off `main`, commit, push, and `gh pr create`. CI deploys every PR to dev.dunderquest.com, which is where changes get reviewed, so a change that's only committed locally can't be seen yet. Never push straight to `main`: it deploys to production.

End with the PR link and a reminder that the preview will be on dev.dunderquest.com once CI finishes.

## Notes go here, not in hidden memory

Anything worth remembering between sessions (decisions, preferences, context) goes in this file, in a PR like any other change, so it can be seen and edited. Don't save it to an agent's private memory store.

## Browse in Rob's Chrome

For anything done in a browser (LinkedIn, YouTube Studio, checking the site), use Rob's own Chrome through the Claude extension (the **Claude in Chrome** tools, `mcp__claude-in-chrome__*`), not the Claude desktop app's built-in browser. Rob asked for this in November 2026: his Chrome is where he's already signed in. Never publish, post or send anything there without his approval.

## Layout

See [README.md](README.md). The site is built by `site/build.ts`. Each game has its own art and trailer tools under `games/<game>/tools/`, run from that game's folder.

## Decisions

- **The site build and CI run on Bun, not Python.** `site/build.ts`, `scripts/fit_pages_limit.ts`, Curb's `tests/verify_rust.ts`, Prince's `tests/verify_git.ts` and the Lieutenant's `tests/verify_sql.ts` are TypeScript run with `bun`, so CI needs no Python. Python stays only for the offline asset tools (`games/*/tools/*.py`, `site/curb_art.py`), which lean on Pillow and numpy and never run in CI. Flatmates.js's `verify_lessons.mjs` stays on `node`, since its page says every snippet is checked against Node.
- **Generating assets is pre-approved.** Generate art, music and SFX with the `tools/generate_*.py` scripts (OpenRouter key in `.env`), or new scripts like them, without asking first. Generated beats placeholder. Keep trailer and marketing assets out of a game's `assets/`, so the web build stays small.
- **Grok is an optional image source, OpenRouter stays the default.** Set `IMAGE_PROVIDER=grok` (environment or `.env`) and the art tools built on `generate_scenery.request_image` generate through the Grok CLI's `grok login`, with no key (`games/dunder-quest/tools/grok_image.py`). Prince of Versions' `scenery.py` follows it too. `generate_assets.py` has its own request and still uses OpenRouter. Backdrops and parallax layers came out well in testing. Sprites are weaker: Grok added hair and shoes to a character the prompt said wasn't a person, and changed another's skin tone between generations, so review them, and don't regenerate one character of a set alone, since it won't match the rest. Each script's prompts were written for the OpenRouter model, and Grok has no alpha, so transparency is a magenta background keyed out; a subject in magenta or hot pink would be cut out with it.
- **Dunder Quest is a Holy Grail homage.** Python is named after Monty Python. Use winking homage names (the Knight Who Says Mi, Tom the Enchanter, the Bridge of Peril), never the films' real character names, and don't quote at length in visible UI, to stay clear of Python (Monty) Pictures' IP. Hidden eggs (`common/eggs.gd`, listed at /admin/eggs) may quote short lines.

## Making a trailer, and keeping it

Each game's trailer is cut by its own `tools/make_trailer.py` from captures of its bot, to a generated music cue; the steps are in that game's `trailer/README.md`. In outline, run from the game's folder: `python tools/trailer_audio.py` (the cue and the effects, through OpenRouter), `bash trailer/capture.sh` (the bot's run at 1920×1080; Prince of Versions also captures its prologue with `bash trailer/capture.sh intro`), then `python tools/make_trailer.py` (`--stills` first, to check the cut). Python comes from mise (`mise exec -- python ...`). Capture one run at a time: several copies of a game recording at 1920×1080 at once brought Rob's machine down (November 2026), which is why The Good, the Bad and the Greedy's `capture.sh` runs its six in turn.

Everything a trailer is made of is git-ignored: `trailer/audio/` (the cue), `trailer/captures/` and `trailer/out/` (the masters and the thumbnail). So it vanishes when a worktree is removed, and the cue can't be made again: generating it twice gives two different pieces of music, and the cut is timed to the one it has. That's how the Prince of Versions trailer was lost in November 2026, cue and all, with only the YouTube copy left. So:

- **After rendering a trailer in a worktree, copy `trailer/out/` and `trailer/audio/` into the main checkout** (`D:\src\dunder-quest\games\<game>\trailer\`), where Curb's, Just One More JOIN's and The Good, the Bad and the Greedy's already are. A Game About Nothing's was rendered in a cloud session, which can't reach that checkout: its masters, thumbnail and cue were sent to Rob as files to save there, and a cloud session that renders a trailer should do the same. The captures (several GB) can stay behind: they can be made again from the repo.
- **The combined Git + SQL trailer** (`site/combo_trailer.py`, for a single post about Prince of Versions and Just One More JOIN, November 2026) is cut from those two 1080p masters, so it needs no cue of its own: run it with `--masters D:\src\dunder-quest` from a worktree, and keep its output in `D:\src\dunder-quest\build\combo_trailer\`.

## Uploading a trailer to YouTube

An agent can do the whole upload, with nothing dragged and dropped. Rob asked for this to be written down after the Just One More JOIN trailer went up this way (November 2026, video `ojUvSRr5Uq8`). It needs the **Claude in Chrome** tools (`mcp__claude-in-chrome__*`), which drive Rob's own Chrome, where he is already signed in to the channel. The app's built-in browser has no file-upload tool, so it can't do this.

The trick is that Studio's drop zone and its thumbnail button each sit on a hidden `<input type="file">`, and `file_upload` hands a file straight to one of those. Never click "Select files" or the thumbnail's "Upload file": they open the operating system's file picker, which the tools can't drive.

1. **Get the form's text.** Build the site to a scratch folder (`bun site/build.ts <scratch>`) and take the title, tags and description from `<scratch>/brand/youtube/index.html`, so chapters and links are the built ones. The page escapes apostrophes as `&#x27;`; type a plain `'`.
2. **Open Studio** in a new tab (studio.youtube.com) and check the dashboard is Dunder Quest's before going on. If it's another channel or a sign-in page, stop and ask Rob.
3. **The video.** Click Create, then "Upload videos". `find` "file input for video upload" returns the dialog's hidden file input; pass its ref to `file_upload` with the 4K master's path. The Details form and the video's link appear in a few seconds.
4. **Title and description.** Select all in the title box and type over the default (the file's name). Click the description box and type the whole description in one go, with `\n` for line breaks. Read both back with `javascript_tool` (`ytcp-uploads-dialog #textbox`).
5. **The thumbnail.** `find` "thumbnail image file input (hidden)" returns the input with id `file-loader` inside the thumbnail uploader; `file_upload` the PNG to it.
6. **Playlists.** Open "Select playlists", tick Trailers and the game's own. A new game's playlist is made there: "New playlist", its name, Public, Create.
7. **The rest of the form**, from `UPLOAD_SETTINGS` in `site/build.ts`: "No, it's not made for kids"; then "Show more": altered or synthetic content No, the tags typed with a comma after every one (the last too), video language English, category Gaming. Typing doesn't filter the language list: `find` the English option, scroll to it and click it.
8. **Publish.** Next three times, choose Public, re-read the title, thumbnail and visibility on screen, then Publish.
9. **Check and wire it in.** Open the watch URL and confirm the title and that it's public, then put the ID in that game's `..._TRAILER_ID` in `site/build.ts` and tick the Upload item in the trailer's README.

Limits and loose ends:

- `file_upload` takes at most 10 MB a call (one call per file; a `browser_batch` of several counts as one call), and only from folders the session may read: the worktree and the scratchpad work, the main checkout may not. **A bigger master goes up in pieces**, as the 38 MB Prince of Versions recut did (November 2026, `BGxekAJEUNA`):
  1. `split -b 9000000 -d -a 1 <master> part_` into a scratchpad folder, and note the master's `sha256sum`.
  2. With `javascript_tool`, add one `<input type="file">` per piece to the Studio page (an `aria-label` like "dq chunk input 0" makes them easy to `find`), and `file_upload` each piece to its own input, one call each.
  3. With `javascript_tool`, join them, `new File([...pieces], "<name>.mp4", {type: "video/mp4"})`, check its SHA-256 (`crypto.subtle.digest`) against the master's, then put it on the dialog's `input[name=Filedata]` through a `DataTransfer` and dispatch a bubbling `change` event. Remove the extra inputs.
  Studio then uploads it as if it had been dropped. The tab goes unresponsive for a minute or so while it does; typing the description then times out but finishes, so wait and read it back rather than typing it again.
- The "Show more" disclosure is now worded "AI use" ("Was AI used to generate or edit your content...", with a list of realistic cases); `UPLOAD_SETTINGS`' answer is still No.
- The steps above leave Studio's defaults for comments, licence, embedding and subscriber notifications, and set nothing for paid promotion, subtitles, cards or the end screen. `UPLOAD_SETTINGS` asks for an end screen (Subscribe, plus another game's trailer); that is still done by hand.
- Element refs change from one visit to the next, so find them fresh each time; the `find` phrases above are the ones that worked.
- Never type a password or solve a CAPTCHA there, and don't touch other videos or the channel's settings.

## Drafting a LinkedIn post with a video

An agent can set up a post in Rob's Chrome, video and all, and leave it for him to press Post. That's how the Git + SQL post was drafted (November 2026). **Never press Post, or anything that publishes, without Rob's approval.**

LinkedIn's composer has no file input until you ask for one: its Media button makes one and opens the system file picker at once, which the tools can't drive. So before clicking Media, use `javascript_tool` to override `HTMLInputElement.prototype.click` (and `showPicker`) so that a click on a file input gives it an `aria-label` like "dq captured file input" and attaches it to the page, without opening the picker. Then click Media, `find` that label, and `file_upload` the video to it (10 MB at most, as with YouTube). In the editor that follows, Thumbnail has a real hidden `image/*` input, which `file_upload` fills directly. Click Next to get back to the text, and restore the original `click` and `showPicker` when you're done.

Type the text after the video is attached, so the links in it don't turn into a link preview. To tag someone, type `@` and part of their name, then pick them from the list: the mention shows bold, and is a span with `data-entity-id`, not plain text.

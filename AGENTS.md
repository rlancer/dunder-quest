# Working in this repo

## Always open a PR

Finish every change by opening a pull request, without being asked: branch off `main`, commit, push, and `gh pr create`. CI deploys every PR to dev.dunderquest.com, which is where changes get reviewed, so a change that's only committed locally can't be seen yet. Never push straight to `main`: it deploys to production.

End with the PR link and a reminder that the preview will be on dev.dunderquest.com once CI finishes.

## Notes go here, not in hidden memory

Anything worth remembering between sessions (decisions, preferences, context) goes in this file, in a PR like any other change, so it can be seen and edited. Don't save it to an agent's private memory store.

## Layout

See [README.md](README.md). The site is built by `site/build.ts`. Each game has its own art and trailer tools under `games/<game>/tools/`, run from that game's folder.

## Decisions

- **The site build and CI run on Bun, not Python.** `site/build.ts`, `scripts/fit_pages_limit.ts` and Curb's `tests/verify_rust.ts` are TypeScript run with `bun`, so CI needs no Python. Python stays only for the offline asset tools (`games/*/tools/*.py`, `site/curb_art.py`), which lean on Pillow and numpy and never run in CI. Flatmates.js's `verify_lessons.mjs` stays on `node`, since its page says every snippet is checked against Node.
- **Generating assets is pre-approved.** Generate art, music and SFX with the `tools/generate_*.py` scripts (OpenRouter key in `.env`), or new scripts like them, without asking first. Generated beats placeholder. Keep trailer and marketing assets out of a game's `assets/`, so the web build stays small.
- **Grok is an optional image source, OpenRouter stays the default.** Set `IMAGE_PROVIDER=grok` (environment or `.env`) and the art tools built on `generate_scenery.request_image` generate through the Grok CLI's `grok login`, with no key (`games/dunder-quest/tools/grok_image.py`). Prince of Versions' `scenery.py` follows it too. `generate_assets.py` has its own request and still uses OpenRouter. Backdrops and parallax layers came out well in testing. Sprites are weaker: Grok added hair and shoes to a character the prompt said wasn't a person, and changed another's skin tone between generations, so review them, and don't regenerate one character of a set alone, since it won't match the rest. Each script's prompts were written for the OpenRouter model, and Grok has no alpha, so transparency is a magenta background keyed out; a subject in magenta or hot pink would be cut out with it.
- **Dunder Quest is a Holy Grail homage.** Python is named after Monty Python. Use winking homage names (the Knight Who Says Mi, Tom the Enchanter, the Bridge of Peril), never the films' real character names, and don't quote at length in visible UI, to stay clear of Python (Monty) Pictures' IP. Hidden eggs (`common/eggs.gd`, listed at /admin/eggs) may quote short lines.
- **Flatmates.js is the second game** (`games/flatmates/`, its own Godot project, page at /flatmates/, game at /flatmates/play/). It teaches JavaScript and is a homage to a Croydon flat-share sitcom. Keep it distinct from Dunder Quest: no quiz duels; the puzzles are scripts that the flatmate you aren't playing runs, and left alone he drifts back to his comfort spot. Use homage names only (Clive, Jazz, Big Ron, Tess from Accounts), never the show's names or lines, and don't name the show in anything public. Its checks are `tests/bot.tscn` and `tests/verify_lessons.mjs`.
- **Curb Your Oxidation is the third game** (`games/curb/`, its own Godot project, page at /curb/, game at /curb/play/). It teaches Rust and is a homage to an LA cringe-comedy series: Rust's borrow checker is the unwritten social contract. Copy the show as closely as possible in everything that is format, tone or trope (the Westside setting, petty etiquette disputes, the improvised-feeling bickering, the hero's squinting stare-downs and suspicious interrogations, black title cards in heavy Franklin Gothic (the show's ITC Franklin Gothic Heavy is commercial, so use Libre Franklin, OFL, in `games/curb/assets/fonts/`, for the game, the site and the trailer), the show's yellow for the name and the accents on black (`Palette.YELLOW`, #fad41c), trailers with the music under every second and a fast cut of highlights (not the game played through; text cards held long enough to read), a freeze frame and a bouncy comic-tuba sting at the end of every scene), with exactly three limits: no real people's or characters' names (homage names only: Barry Danvers, Gil and Sharon Greene, Carol, Lamont, Ted Pruitt), no verbatim catchphrases or lines from the show, and no recreation of its theme tune (original music in the same style and instrumentation is fine). Don't name the show in anything public: the game, the site (brand kit included), the trailers and the video descriptions. The one exception is Rob's own social posts, which may say the game is "inspired by" the show by name, with nothing implying the network is involved. Their copy on the brand kit's launch page (`CURB_LAUNCH`) names it too, since it's what he pastes. Keep it distinct from the other two games: no quiz duels and no flatmate running your script; a plan plays in Barry's head first and Sharon interrupts at the line the borrow checker rejects, with the real rustc error code. Never teach anything that isn't real Rust. Its checks are `tests/cases.gd`, `tests/bot.tscn` and `tests/verify_rust.ts` (which compiles every plan with rustc; CI runs it).
- **Prince of Versions is the fifth game** (`games/prince/`, its own Godot project, page at /prince/, game at /prince/play/; a card on the home splash). It teaches Git and is a spoof of a certain palace-run platformer and its time-rewinding sequel: the dagger that turns back the sands is version control, and it only goes back to a commit. Every torch, gate and bridge in a room is a one-line file in a Git repo modelled in GDScript (`git/repo.gd`), which hashes commits the way Git does, so the ids on screen are real. The player never types: the dagger's console is buttons, each showing the exact command it runs and Git's own output. The exit opens only on `main` with a clean tree. Design, curriculum and level list are in `games/prince/GAME.md`; Act I (five rooms: commit, reset, revert, branch and merge, a merge-conflict boss) is built, Act II (stash, cherry-pick, bisect, reflog, rebase) is designed only. Never teach anything that isn't real Git: `tests/replay.gd` runs every room's solution and a set of probes through the model, `tests/verify_git.ts` repeats them with the real git and demands the same ids, files, conflicts and output, and `tests/bot.tscn` plays every room (`bash tests/check.sh` runs all three; CI runs it). Same limits as the other homages: homage names only (the Prince, Grand Vizier Rebasir, Princess Shirin), no copied sprites, rooms, levels or music, and don't name the original in anything players see. Art: `tools/paint.py` (sprites, tiles), `tools/scenery.py` and `tools/music.py` (generated), `tools/sfx.py` (synthesized), `tools/site_art.py` (the page's screenshots and social card).
- **Mission Silicon, a fourth game about building web apps with AI, was dropped in November 2026** (Rob: it turned out to be a dud). Its code is in git history before this change; don't build on it.
- **The home page is a splash of every game, and Curb leads it.** Rob expects Curb Your Oxidation to be the hit, so it gets the big title card (trailer, Play button) at the top of `/`, and the bar's Play button goes to it; Dunder Quest, Flatmates.js and Prince of Versions follow as cards. Dunder Quest's own page is `/dunder-quest/` (`buildHome`); its game stays at `/play/` and its lessons at `/lessons/`.
- **Trailers are YouTube-first.** The 4K master and the YouTube thumbnail are primary. Steam is deferred, so keep the 1080p master Steam-compatible.
- **One YouTube channel for every game:** [@dunderquest](https://www.youtube.com/@dunderquest). Channel art, copy and each video's upload form live on /brand/youtube/ (`buildBrandYoutube` in `site/build.ts`). Link that channel, not any other.

## Why it's a learning game

Rob is dyslexic and was failing his spelling tests until his dad wrote him a spelling game in BASIC; after that he got 100 on every one. His kids are 5 and 2 (as of October 2026), too young for Python, "but maybe some day". He offered this for launch copy. Use only these facts and don't embellish them (no made-up computer, age or names).
